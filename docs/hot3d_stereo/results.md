# 用 HOT3D 验证双目手腕测距 + 双目硬件选型（2026-10-10）

> 标记说明：**【实测】**= 真实图像上跑 WiLoR 得到的数；**【仿真】**= 把 HOT3D 真值手放进虚拟双目、加上【实测】的 WiLoR 二维误差算出来的预测。所有数字都由 `scripts/eval_hot3d_stereo.py` 生成，没有手填。

## 一句话结论
- **双目确实把手腕误差压到 2 cm 附近**：真实图像上手腕误差中位数 **1.22 cm**（单目 2.71 cm），75% 的手达到 2 cm 以内（单目 33%）。
- **但还不是“每帧都 2 cm”**：p90 是 3.4 cm，尾部来自 WiLoR 认错/认偏的帧，要靠 QC 和平滑处理。
- **选硬件最要紧的三件事**：① 两目**硬件同步**；② 基线**≥ 6 cm，最好 8–10 cm**；③ 视场角**≥ 100°**（75° 会有约 1/3 的手不在两个镜头里）。分辨率、全局/卷帘快门、60 fps 影响很小。

## 数据与做法
- 数据：HuggingFace `bop-benchmark/hot3d`（HOT3D-Clips，无需点击协议即可下载；协议 PDF 在仓库根目录 `hot3d_dataset_license_agreement.pdf`）。用了 4 段 **Quest3** 训练片段（clip 000000/000300/000700/001100，4 个不同参与者），每段每 3 帧取 1 帧，共 200 帧、400 只手。
- Quest3 两个黑白 SLAM 鱼眼相机：1280×1024，**基线 6.4 cm**（和你计划的 OV9281 6 cm 几乎一样）。
- 流程：鱼眼 → 去畸变成针孔（并转正 90°）→ 左右图各跑一次 WiLoR → 21 个关节逐点三角化 → 和 MANO 真值比较（世界坐标，米制）。
- Aria 的两个 SLAM 相机朝向左右两侧，抽查 30 帧里**没有一只手同时出现在两个镜头里**，不能做双目，所以只用 Quest3。这也说明：**两个镜头必须朝同一方向、视野大量重叠**。

## 一、【实测】真实图像结果（Quest3，CPU 上跑 WiLoR）
| 指标 | 单目 WiLoR（左目，已知真实内参） | 双目三角化 |
|---|---|---|
| 检出率 | 左目 91.6% / 右目 90.1% | 两目都检出 86.0% |
| 二维关键点误差（中位数） | 10.9 px / 10.6 px | — |
| 手腕三维误差 中位数 / 均值 / p90 | 2.71 / 4.81 / 6.26 cm | **1.22 / 3.20 / 3.41 cm** |
| 其中“深度方向”误差中位数 | — | 0.88 cm |
| 21 关节平均误差 MPJPE 中位数 | 4.09 cm | **2.12 cm** |
| 手腕 ≤ 2 cm 的比例 | 33% | **75%** |

（统计口径：两目都检出的 320 只手。均值远大于中位数，说明有少数“认错手/认偏”的大误差帧。）

**按手离相机距离**（双目 / 单目 手腕误差中位数）：
| 距离 | 样本 | 双目 | 单目 |
|---|---|---|---|
| < 30 cm | 54 | 1.23 cm | 2.24 cm |
| 30–40 cm | 226 | 1.27 cm | 2.92 cm |
| 40–50 cm | 35 | 1.09 cm | 2.03 cm |
| 50–60 cm | 5 | 1.76 cm（样本太少） | 3.73 cm |

**【实测】分辨率减半（512×640）**：同样 200 帧，二维误差从 10.1 px 降到 5.0 px（正好减半），双目手腕误差中位数 **1.26 cm**、≤2cm 占 78%——和全分辨率几乎一样。原因：WiLoR 会把手裁出来缩放到固定 256×256 再识别，所以“像素多”帮不上忙。

> 注意：这里的单目误差（2.7 cm）比之前 EgoDex 上的 22 cm 好很多，是因为这里给了 WiLoR 真实相机内参、且手离得近；单目在 EgoDex 上的问题在双目下不存在。

## 二、【仿真】硬件选型表
做法：取 HOT3D 全部帧（4 段 × 150 帧）的真值手轨迹，放进一个虚拟平行双目；每个关节加上**真实测得的 WiLoR 左右目成对二维误差**（保留两目误差的相关性，剔除 4.9% 认错手的帧）；按配置模拟基线、视场角、分辨率、同步偏差、卷帘快门，然后三角化。
- **校准检查**：用 Quest3 自己的几何做仿真，手腕中位数 1.28 cm、p90 4.0 cm，与【实测】1.22 / 3.41 cm 接近，仿真可信（p90 略偏悲观）。
- **分辨率模型**：像素误差 ∝ 焦距^α，α 由上面“分辨率减半”实测拟合 = **1.01**（即误差按视角不变）。超出实测范围（焦距 >504 px）是外推。表中另给 α=0（像素误差固定、分辨率越高越准）的乐观上界。
- 括号是自助法 95% 置信区间（只反映采样波动，不含模型误差）。覆盖率 = 手腕同时在两个画面里的比例，相机朝向沿用 Quest3 左 SLAM 相机（向前下方）——你实际装的俯仰角不同，覆盖率会变。

| 配置（默认：75°、1280×800、全局快门、硬件同步、6 cm） | 手腕中位数 cm | 手腕 p90 cm | MPJPE 中位数 cm | ≤2cm 比例 | 两目覆盖率 |
|---|---|---|---|---|---|
| 基线 4 cm | 1.78 [1.72–1.87] | 6.24 | 3.28 | 54% | 69% |
| **基线 6 cm（BOM 方案 A/B）** | **1.36 [1.30–1.43]** | **4.26** | 2.35 | **67%** | **68%** |
| 基线 8 cm | 1.15 [1.12–1.20] | 3.37 | 1.90 | 75% | 68% |
| 基线 10 cm | 1.03 [1.00–1.07] | 3.02 | 1.65 | 80% | 68% |
| 视场角 100° | 1.29 [1.24–1.34] | 4.18 | 2.26 | 68% | **82%** |
| 视场角 120° | 1.30 [1.24–1.35] | 4.26 | 2.28 | 69% | **100%** |
| 640×400 @75° / @100° | 1.36 / 1.29 | 4.26 / 4.18 | 2.35 / 2.26 | 67% / 68% | 68% / 82% |
| 1600×1200 (AR0234) @75° / @100° | 1.36 / 1.30 | 4.34 / 4.10 | 2.33 / 2.25 | 68% / 68% | 70% / 91% |

分辨率 α=0 乐观上界（手腕中位数）：640×400@75° 1.65 cm，1280×800@75° 0.82 cm，1600×1200@75° 0.65 cm。我们的实测支持 α≈1，所以按主表看。

**【仿真】RGB 与双目时间差**（只影响“彩色画面”和“双目标签”的对齐，不影响双目精度）：手腕在这段时间里移动的距离，10 ms：中位数 0.15 cm / p90 0.58 cm；17 ms（30fps 半帧）：0.26 / 0.98 cm；33 ms（错一整帧）：0.51 / 1.91 cm，92% 仍 ≤2 cm。

## 三、选型建议
| 规格 | 结论 | 依据 |
|---|---|---|
| 两目硬件同步（≤1 ms） | **必须** | 10 ms 偏差 ≤2cm 比例 67%→62%，30 ms →50%，p90 4.3→7.0 cm |
| 两镜头同向、视野大量重叠 | **必须** | Aria 侧向 SLAM 相机 0 帧可用 |
| 基线 ≥ 6 cm，**建议 8–10 cm** | 必须 ≥6；8–10 强烈建议 | 4→6→8→10 cm：≤2cm 54%→67%→75%→80% |
| 视场角 ≥ 100° | **强烈建议** | 精度不变，覆盖率 68%→82%（120°：100%）；HOT3D 本身就是鱼眼，去畸变后 WiLoR 照样能用 |
| 分辨率 | 不重要，640×400 就够 | 实测分辨率减半精度不变（α≈1.0） |
| 全局快门 | 可选（锦上添花） | 两目同步的卷帘快门只差约 0.05 cm（HOT3D 手速不快；快速动作时差距会变大，未验证） |
| 60 fps | 可选 | 只在两目不同步时有帮助 |
| RGB 与双目同步 | ≤ 17 ms 即可 | 半帧偏差 p90 < 1 cm |

**对 BOM 的意见**：方案 A/B 用的 DECXIN OV9281 USB3 双目（硬件同步、全局快门）方向正确，【仿真】预测手腕中位数 1.36 cm、67% 帧 ≤2 cm。下单时只改两点：
1. **问清基线，优先选 8–10 cm 的**（预测中位数 1.15/1.03 cm，≤2cm 75%/80%）；
2. **镜头选 100° 左右，而不是 BOM 里写的 75° 无畸变**——75° 会丢约三分之一的手。
主控、RGB、IMU 不影响这些结论。方案 A 已经够用，方案 B 的升级项不影响手腕精度。

## 四、还没解决 / 局限
- p90 3–4 cm 来自 WiLoR 的偶发大错（认错手、手指被挡），下一步：用两目重投影误差做 QC 剔除 + 时间平滑，再测一次。
- HOT3D 动作偏慢（手腕中位速度约 15 cm/s），快速动作下快门和同步的影响会更大。
- 覆盖率依赖相机俯仰角，装好设备后要用自己的录像复测。
- 1600×1200 的焦距超出实测范围，是外推。
- 只测了 200 帧、4 个人；CPU 上跑 WiLoR 约 1 秒/张图。

## 复现
```bash
# 依赖：pip install git+https://github.com/facebookresearch/hand_tracking_toolkit smplx；WiLoR 环境变量同 headcam/hand_pose.py
python scripts/eval_hot3d_stereo.py run --clips data/train_quest3/clip-000000 ... --stride 3 --max-frames 50 --out preds.npy
python scripts/eval_hot3d_stereo.py run ... --res-scale 0.5 --out preds_half.npy
python scripts/eval_hot3d_stereo.py report --preds preds.npy --out report.json
python scripts/eval_hot3d_stereo.py simulate --preds preds.npy --low-preds preds_half.npy --out sim.json
python scripts/plot_hot3d_stereo.py report.json sim.json docs/hot3d_stereo/hot3d_stereo.png
```
